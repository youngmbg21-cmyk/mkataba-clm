Negotiate Moves Out

Negotiation stops being a tab inside one agreement and becomes a place of its own in the main menu — with a door in from the Document tab and a way back out.

Agreed 12 Aug 2026 Design only · nothing built yet Desktop and phone
Decision

What was decided

Four things, and everything below follows from them.

  • The contract room keeps its tab row, minus one: Key terms · Document · Signing · History.
  • Negotiate becomes its own door in the left menu, directly under Contracts.
  • You get into a negotiation by pressing Open Negotiate on the Document tab.
  • The negotiation screen carries no room tabs — it is its own screen, not a tab of the contract.

Two follow-up answers shape the rest: pressing Negotiate in the menu reopens the last negotiation you were in, and the negotiation screen carries a back arrow to the contract. The phone changes the same way.

Worth knowing

Negotiate is already a full screen behind the scenes — it only dressed up as a tab by drawing the same tab row at the top. So this is a change of doors and signposts, not a rebuild of the negotiation desk itself.

When you are standing in a negotiation, Negotiate is the lit door

Today the negotiation screen lights up Contracts, because it had no door of its own. It now lights Negotiate — and only Negotiate. One screen, one lit door, or the menu starts disagreeing with the page beside it.

The tooltip should name what it will open

Because the door reopens the last negotiation, hovering it should say which one: “Reopen: Mutual NDA — Saw Sawa LLC.” Cheap to do, and it removes the only real surprise in the design.

The room

Four tabs, and one solid button

Negotiate comes off the tab row. Its amber count goes with it. In its place, on the Document tab, the Open Negotiate button — which already lives at the right-hand end of that row — becomes the single way in.

The button must stop hiding itself

Right now that button only appears once changes have actually been filed — because until then, the tab was there anyway. With the tab gone, hiding it leaves a fresh draft with no door at all. It should always be on the Document tab, changing only its words:

  • “Start negotiating” — nothing filed yet.
  • “Open Negotiate · 3 waiting” — a negotiation is running, and this is what it owes you.

The other three tabs still have to admit a negotiation is running

The amber tab count was how someone on Key terms knew changes were waiting. That signal must not vanish with it. The round line already under the contract title on every tab (“Round 1 · updated 12 aug 2026”) is the right place to carry it — “Round 1 · 3 changes waiting on you”, in amber, pressable, going straight to the negotiation.

The screen

The negotiation screen, and the way back

No tab row. Instead, a header that answers three questions a negotiator asks constantly: which agreement is this, where am I in it, and how do I get out?

  • The back arrow returns to that contract's Document tab — the tab you came from, so the journey is a loop and not a maze.
  • The contract name is part of the back door, not just a label: pressing the title does the same thing as the arrow. It is the biggest target on the screen and people will aim at it.

The one thing that gets worse

Checking the value or the signing route mid-negotiation used to be one click on a tab. It is now two: back, then the tab. That is the price of the focused screen you asked for, and it is a fair one — but if it starts to bite, the fix is a small “Go to…” menu beside the back arrow offering Key terms and Signing. I have not put that in the design; it is the first thing to add if the complaint appears.

Reopening

What “reopen the last one” actually has to handle

The rule is simple; three situations sit underneath it and each needs an answer, or the door breaks the first week.

When you press NegotiateWhat happens
You were in one, and it is still liveIt opens, on the same reading and the same filter you left it on. This is the normal case.
You have never opened oneAn empty screen that says so and offers the way in: “No negotiation open. Pick an agreement to negotiate” — with a short list of the agreements that currently have one running.
The last one is signed, closed, or no longer yours to seeSame empty screen with the same list. Reopening a finished argument would be worse than showing nothing.

The memory is per person, per computer, and survives closing the browser. It never travels to anyone else.

Said once, then left alone

That empty screen is doing the job a list of live negotiations would have done permanently. If people press Negotiate and land on it often — or start using it to jump between agreements — that is the signal the door wants to be a list after all. Worth watching, not worth arguing about now.

The number

The amber count changes meaning

On a tab it counted this agreement's changes. On a menu door it cannot — a door that shows one agreement's number while sitting above every agreement is simply wrong.

  • On the menu: how many changes are waiting on you, across every live negotiation you can see. Amber when there are any, gone when there are none.
  • On the negotiation screen: this agreement's own count, in the header pill.
  • On the contract room: in the round line under the title, on all four tabs.

One number in each place, each counting the thing it sits next to.

Phone

The phone changes the same way

Half of this is already true on the phone. The contract screen there has only Document, Key terms and History — Negotiate was never a tab — and the negotiation opens as its own full screen under a back bar. That back bar is exactly the back door this design asks for.

So the phone needs one thing: Negotiate joins the bottom bar, with the same count and the same reopen-the-last-one behaviour.

Elsewhere

Everything that already jumps into a negotiation

A good number of buttons around the app already open the negotiation directly. All of them keep working — they will simply land on the new standalone screen instead of a tab. Which is why the back arrow is not a nicety: it is the only way out for every one of them.

What does not change at all

The counterparty's page never had these tabs and is untouched. Sharing, signing links, the approval chain, internal review, the negotiation desk and every rule about who may do what all sit underneath this and are unaffected. Nothing about how a change is filed, held or sent moves.

Open

Still to decide

  1. Where does the back arrow land — Document, or wherever you came from?The design says always Document. It is predictable, and “wherever you came from” means the same button does five different things.
  2. Does the empty screen list live negotiations, or just point at Contracts?A short list is more useful and costs little. It is also, quietly, the negotiations list — which is why I would keep it short and plain rather than let it grow into a second register.
  3. Should “Negotiate” be renamed “Negotiations”?Everything else in that menu is a noun — Contracts, Calendar, Insights, Templates. A verb in the list reads as a button rather than a place. Small, but it is the word people will see a hundred times a day.

Design only. No code has been written or changed. Once these three are settled the build is a navigation change — a door added, a tab removed, a header rewritten and a phone bar widened — plus the tests that keep them honest.
