**THE TEST, AND BOTH HALVES MUST PASS**, asked about the SCREEN:
1. Does it say something the screen does not already say? A control, count, heading or status word twelve pixels away that carries the fact makes the band that fact printed twice, and the second printing reads as an alarm.
2. Is it about work owed, or a promise made — and does it carry the act?

## HOW TO TEST ECONOMICALLY (owner-asked 16 and 24 Aug 2026)

**"Do not run the full test suite during incremental edits. Only run the specific test file directly related to the changed code."** Every edit before you believe you are finished is incremental, including fixes to a test you just broke. Run the affected files together in ONE command (`node --test --test-reporter=dot test/<a>.test.js test/<b>.test.js`) until they pass; the full suite runs ONCE when you believe you are finished, and again only if that run found something.

- Full suite: **5m05s**, 6,729 tests in 1,355 suites, 0 red (re-measured 12 Sep 2026; it read ~4,100 on 21 Aug — the runner is the authority, re-measure before quoting it). A browser file starts a real Chrome and costs 11–40 SECONDS.
- `npm run lint` FIRST — seconds, zero errors is the bar (the ~137 warnings are unused locals; eslint.config.js explains every rule and holds KNOWN_ABSENT). It is the only check that asks "is every name being called a name that exists".
- While working: only the test files the feature's section names. One browser file per screen changed; re-run only after a change to what it measures.
- `node test/chromium/run-all.js` runs the whole browser set (four at a time) — what CI runs, not what you run while working. A file expected to fail is named in KNOWN_RED **with its reason**, printed on every run. **Take a file off that list the day it goes green.**
- **A TEST WHOSE ANSWER DEPENDS ON THE DAY IT RUNS IS WORSE THAN NO TEST.** Fixture dates carrying a calendar claim are built with `monthSpan(off)` or quarter boundaries, never by counting days from today (f183 was red 264 days of 730). Faking node's clock does NOT move jsdom's — rule out the instrument before believing the finding.

## STANDING LESSONS — the defect classes this codebase has paid for repeatedly

Each of these is recorded at length in docs/MAP-HISTORY.md; they are collected here because a new section keeps rediscovering them.

- **THE FILES ARE ES MODULES.** A top-level function is NOT a global; another module reaches it only through the `Object.assign(window, {…})` at the end of its file. A name missing from that list is unreachable, and every caller guarded on `window.foo && …` silently takes its fallback (the rlPaperFootHtml family — a placeholder drew for a year). **f232 is the net**: every `window.foo` READ must be a published name. Its DELIBERATE list is empty; `state` is read BARE everywhere (core.js declares it const; `window.state && …` silently disabled the review gate once). f48 catches the opposite fault (two modules publishing one name) and f232-6 catches one module DECLARING a name another publishes (a hoisted private `lsGet` once captured setView's calls and lost the reader's page on refresh).
- **THE BROWSER HARNESSES DO NOT LOAD index.html.** test/chromium/*.html, test/world.js and test/portalworld.js build their own script lists as CLASSIC scripts — so a new file in js/ is not on them until added, and an unpublished name resolves there when it would not in the product. Run f232 before believing a green browser run on anything that crosses a module boundary.
- **A GUARD THAT IS ALWAYS FALSE, A RULE THAT LOSES A CASCADE FIGHT, AN ATTRIBUTE NOTHING LISTENS FOR, A COMMENT THAT SWALLOWS THE RULE UNDER IT** — four costumes of one fault: nothing errors, nothing logs, the source looks correct. When a rule looks right and the screen looks wrong, MEASURE the computed value in a browser before editing the declaration; fix cascade fights by SCOPE, never `!important`. Never write the CSS comment terminator inside a CSS comment (say "terminator"). Never a backtick in a `<style>` block emitted from a JS template literal — a balanced pair EVALUATES what is between them; f236 is the net.
- **THE COMPILED TAILWIND BLOB IN index.html IS GENERATED.** Never edit it; write overrides in HaTi's own sheet at equal specificity, later in source. Find it by its signature, never a line number. `font-600`, `font-700`, `.sr-only`, `.rounded-full` and four other classes are defined in HaTi's sheet because nothing else defined them.
- **THE GETTER TRAP.** An object literal freezes load-time language; `{...f}` and `Object.fromEntries` INVOKE getters. Use per-key getters and copy by descriptor. A label that is also a RECORD keeps English (RELATION_DOC_WORD, ROLE_LABEL, clauseLabel, audit lines).
- **READING MUST NOT WRITE.** `negoChanges`/`negoAllChanges`/`negoRound`/`negoClauseList` call `negoInit`, which CREATES a negotiation and stamps clause ids. A count or a reading over the book reads `c.changes` and `c.negotiation` RAW.
- **THE LIGHT LIST.** In server mode `state.contracts` is the LIGHT list and HEAVY strips `audit`, an upload's extracted text and more. A reading off the trail is right locally and empty in production (the dashboard's "raised by me", Reports' cycle time, the desk's renewal note). Carry the fact as transport (`_raisedBy`, `_hasBrief`, `_renewalPrep`), stripped on save.
- **THE SERVER IS THE WALL; THE BROWSER IS COSMETICS.** A rule enforced only in pixels holds until somebody sends the request. Guards on PUT /api/contracts/:id are asked as a DIFFERENCE against the STORED record. A route must never read an address out of the body (the open-relay rule) — it looks the person up.
- **"SENT" MUST MEAN SENT.** `mailReport(r)` is the one shape — sent / configured / outbox / error; the outbox is honest delivery, not failure. A `sent_at` stamped whatever the provider did is a lie for the life of the record.
- **A CAP IS A FACT, NEVER A SILENT TRIM.** What was left out is counted and said. An answer cut short (stop_reason) is not an empty answer and is not cached as a whole one. **An absence is stated, never guessed** — null is the honest answer where the record says nothing.
- **A BARE `toast(msg)` PRINTS NOTHING** — kinds are ok / warn / err (TOAST_KINDS, every kind has a dwell, none is zero). An act that leaves the building confirms itself with 'ok'. A stage stub kinder than the real function turns its test into a description.
- **PIN THE RELATION, NOT THE NUMBER.** A test pinning a literal px, colour or count where the claim is a relation costs an edit at every retune and passes on the wrong thing. `test/tokens.js` resolves a token so a test can read a number without typing one.
- **A CHECK THAT PASSES AGAINST THE PARENT IS A DESCRIPTION.** Run a new check against the commit before the fix; a block that hand-writes the shape the product produces passes before the product could produce it. Every driven half of a browser file is GUARDED so a build without the feature REPORTS its failures rather than timing out. A probe that throws proves nothing.
- **PHOTOGRAPH WHAT YOU BUILT.** Read the rendered page, not the source — a card contradicting itself, a dead press, an empty tile with a tick, a rule scoped to the wrong home, are all only visible on screen. Playwright scrolls an element into view before clicking; `.nego-scroll` animates; re-query after a repaint; a probe's own sentinel is not data.
- **THE CLOTHES FOLLOW THE BUILDER.** A control drawn by a shared builder must be dressed by a rule that reaches every home it is drawn in; a rule scoped to one home leaves the other unstyled. Two surfaces may DRAW differently; the READING (which change a clause shows, whose move, is this overdue, which playbook applies) never may — find the question both answer and make it one function.
- **A STANDALONE DOCUMENT CARRIES NO `:root`.** healthreport.js, weekly.js, negoHistoryExportHtml, the memo's clipboard HTML: every value there is a literal; a `var()` resolves to nothing. Charts paint to canvas and need real values too.
- **CHECK THE REMOTE BEFORE MEASURING.** Start from the latest main; "this was already broken" is proved by running the file in a worktree at unmodified main, never asserted.
- **THE COLOUR CENSUS** (theme-tokens-verify, 20 screens × 2 themes) is re-recorded ONLY by somebody deliberately owning a palette change, audited value by value as a SET DIFFERENCE first, in the same commit — never to make a red run go away, and never absorbing somebody else's regression (restore that line by hand). Re-measure before quoting its score.
